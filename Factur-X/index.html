Le premier caractère indique la catégorie (B = bien, S = service). Au-delà de B1/B2/S1/S2, la signification exacte de chaque code dépend de ta plateforme (PDP/PPF) — vérifie avec elle si tu hésites.

Portée technique. Le XML suit la structure CII (Cross Industry Invoice), profil EN 16931. Le PDF intègre ce XML en pièce jointe, un profil colorimétrique ICC (sRGB) et des métadonnées XMP (PDF/A-3, part 3 / conformance B), avec une police réellement incluse dans le fichier (Noto Sans, sous-ensemble) plutôt que référencée — c'est cette dernière exigence qui rend un PDF/A valide ou non. Le statut affiché après génération indique si tout a pu être intégré. Cela reste une conformité construite manuellement, pas un moteur PDF/A certifié : avant tout envoi via une plateforme (Chorus Pro, PDP…), valide le fichier avec un outil officiel (Mustang Project, FNFE-MPE, veraPDF).
